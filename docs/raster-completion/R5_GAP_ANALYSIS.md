# R5 initial gap analysis

Baseline: main `7538ee31d119276e37eae56c6694c9113f7e2e03`, verified 2026-10-24. Branch `codex/r5-transform-geometry-engine` starts directly from that commit. R1/R1.1/R2 and their release audit are present. Draft R3 PR #14 (`848ebf8` at audit) and AI F1 PR #6 (`1b71cb2`) are separate; no R4 branch/PR was present in the returned open-PR/branch inventory. No development branch is incorporated. This document records the pre-implementation audit; final measurements/results belong in the implementation/test reports.

| Feature | Initial classification | Evidence / smallest safe path |
| --- | --- | --- |
| Affine Free Transform, pivot, width/height, aspect lock, move/rotate/flip | Already implemented and verified by existing tests | `transform.ts`, `transform-transaction.ts`, ProTransform/ProCanvas; matrix/alpha/native/browser tests. Reuse source-backed metadata, never resample a preview into a source. |
| Group/linked transforms, locks, clipping and masks | Already implemented, integration audit required | Existing affine forest and group mask coverage. Add targeted mask-only behavior; prohibit unsupported nonlinear mask-only editing. |
| Quick content rotations and percentage sizing | Partially implemented | Numeric angle and axis sizes exist; add explicit +/-90/180 and percentages using the same affine fields. Keep view rotation separate. |
| Keyboard nudging and configurable large step | Missing | Add document-space Move/Free Transform nudging with lock checks and a UI-only step preference; no schema change. |
| Snap/guides, zoom/pan/view rotation | Already implemented and verified by existing tests | Reuse precision.ts/viewport.ts including R2 navigator correction; verify transform/crop after quarter-turn view rotations on all requested viewports. |
| Active-mask targeting during geometric edits | Implemented but defective | Mask paint mode exists, but choosing Free Transform still transforms layer content. Use existing mask placement matrices for a clearly labeled affine mask target. |
| Non-destructive crop, straightening, eight handles, thirds, Apply/Cancel/Reset | Already implemented and verified by existing tests | Existing crop metadata and output matrix retain off-crop artwork after native reopen. Preserve this implementation. |
| Canvas Size | Partially implemented | Top-left only. Add nine anchor positions with one validated document-coordinate translation of artwork, ordinary/group/unlinked masks, selection frames, crop, artboards, guides and Dialogue review regions. No source resampling. |
| Image Resize | Partially implemented workflow | Existing native `imageSize` genuinely resamples final composite using nearest/bilinear/Catmull–Rom bicubic/Lanczos3, retaining layer coordinates. Add percentage mode and explicit pending-size cancellation/summary; document output-grid semantics, not destructive source resizing. |
| Skew, inverse/bounds, four-corner perspective, alpha-aware projective export | Already implemented and verified by existing tests | Reuse affine composition/inverse, homography and premultiplied projective minification; extend combined view/mask/UI tests. |
| Warp | Already implemented, bounded | Existing smooth3x3 quadratic surface and10% control displacement remain. No optional mesh expansion in R5. |
| Transform selected pixels | Missing floating-content transaction | Stable selection coverage exists, but transforms target whole layers. No native floating-cut/paste primitive; avoid interpreting an active selection as a silent whole-layer selection transform. Provide explicit whole-layer scope feedback and document any unimplemented selected-pixel lift/move rather than duplicating R4 selection semantics. This is an R5 document-staging gap, not an invented dependency on an unavailable R4 API. |
| Preview/commit/stale target safety | Partially implemented | Existing source-backed preview and history; transform draft lacks an explicit captured document origin and target-plane flag. Bind draft to its original immutable revision/IDs; save only committed data; fail/cancel stale drafts. |
| Resource validation, undo/native/export | Already implemented; additional regression needed | Existing16.8MP/16384-side ceiling plus constrained-device budgets, asset/history caps, validate-before-record and R1.1 predecode policy. Do not widen or bypass them. |

Implementation order: baseline validation → pure compatible canvas/mask/pose helpers and mathematical tests → transform/canvas/output controls and revision-bound lifecycle → real UI/native/pixel regression at1440/768/390/360/320 → measured native transform/resampling workloads → full cross-studio checks and exact-HEAD CI → Draft PR report. No brush renderer, selection representation, native schema, homepage, deployment settings, R3/R4/F1 branch or production edits are authorized.
