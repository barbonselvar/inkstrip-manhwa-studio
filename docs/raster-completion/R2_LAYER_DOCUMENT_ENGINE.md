## Confirmed defects and fixes

1. **Orphan clipping on reorder.** `reorderLayers` validated the general tree but allowed an individual clip to become the first sibling. Legacy orphan rendering intentionally hides such clips, so an ordinary reorder could unexpectedly hide artwork. After constructing/validating a candidate, new clipped roots must still have a base; otherwise the transaction throws before publication/history recording. Legacy imported orphan documents still load with their existing safe hidden behavior and can release clipping; they are not silently discarded.
2. **Stale mask-edit target after Undo.** Mask targeting was UI state outside document history. Undo could remove the mask while leaving its editing mode armed, allowing another stroke to recreate it. A real browser regression first failed with `undoing mask creation must disarm mask-edit mode`. The workspace now clears that mode when the active mask disappears. Redo restores the mask data; the row target explicitly re-arms editing. Native source/paint strokes remain unchanged.
3. **Unnecessary thumbnail rendering.** Every document change restarted the thumbnail worker and requested all layers. A 36-layer visibility-toggle sample recorded three additional requests (one completed 36-thumbnail response; the other requests had no completed reply in the observation window). The cache uses the same isolation contract as actual thumbnail rendering; unaffected entries reuse URLs, while affected layers/ancestors refresh.
4. **Independent mask-plane thumbnail allocation.** The old preview scale considered only layer dimensions. A 1×1 layer with a valid 4096² independent mask could request a full 4096² temporary preview mask. Scale now considers both frames, keeping the raw thumbnail plane <=96×72. The native mask compositor is unchanged.
5. **Low-zoom mobile artboard regression, fixed before completion.** The new view chrome made a fitted board44.66×33.5px;44px hit regions overlapped, and DOM paint order selected the bottom-edge handle when the user touched the southeast corner. After nearest-handle correction, a strict movement assertion also exposed independent CSS width/height rounding. Geometric acquisition reserves the center for movement; measured quarter-turn axis calibration plus matching SVG sizing restores exact source coordinates. The unchanged Artboard suite passes desktop/320/390 after the fix. The first complete27-suite run was26pass/1fail, retained as evidence; the complete suite was rerun on the corrected source (27/27 passed). It is rerun again with the transaction fixes and the additional gesture suite.
6. **Partial thumbnail URL allocation.** New URLs are staged before changing existing cached entries. An injected failure on the second allocation revokes staged URLs and leaves document data intact. Unmount, deletion and replacement revoke owned URLs; workers are disposed when jobs finish or are superseded.

7. **Concurrent canvas/history transactions (High).** A real pointer-held Ctrl+Z test reproduced two strokes after Undo should have left zero: pointer-up committed a document captured before Undo. A separate property-edit probe reproduced an unfinished stroke becoming committed along with opacity. Canvas gestures now capture their immutable history origin; document changes cancel their preview, and the final commit checks the live history reference. Property panels edit the committed document while the existing renderer/canvas alone consume transient previews. This is a separation of existing UI state, not a new document engine. Undo/Redo, stale rectangle selection and interleaved opacity edits are tested through native downloads.
8. **Mid-stroke mask-plane switching (High).** A pointer-held mask eraser followed by a keyboard toggle of Paint layer mask left zero mask strokes and redirected the operation to artwork. Each gesture now captures its original mask/layer plane, including coordinate mapping and history label. The toggle applies to the next gesture. Native mask/paint stroke counts and the actual transparent exported pixel are verified.

## Viewport geometry and interaction contract

`viewport.ts` implements fitting, forward/inverse mapping and rotation around the viewport center. The inverse removes measured pan/zoom and view rotation before adding the document-frame origin. Quarter-turn mapping calibrates both local axes from actual CSS bounds, accounting for independent subpixel layout rounding. SVG overlays use matching per-axis sizing instead of a tiny aspect-ratio letterbox. It does not infer document coordinates from an axis-aligned bounding rectangle of rotated artwork. This matters for nonsquare images, nonzero artboard origins, zoom, pan, touch and handle hit testing.

CSS rotates the existing composite, selection coverage, SVG guides/handles and cursor together. Distances for snapping/hit targets still use uniform `fit * zoom`; a view rotation preserves those distances. Two-finger pinch/pan preserves the view angle. Reset preserves zoom and the source point under the viewport center; Fit preserves the current angle and refits. Rotation is ignored during an active pointer gesture to avoid mixing coordinate frames mid-stroke. Controls distinguish **canvas view** from layer/image rotation and do not resample pixels.

Shortcuts do not intercept property typing or menus/dialogs. Existing numeric-transform Enter/Apply and Escape/Cancel behavior is retained and regression-tested. View orientation resets on closing/reopening the editor, and consumes no document Undo state. Layer transforms remain independently editable and serialized.

## Document and history compatibility

No field, document/envelope version, database store or migration was added. Existing internal document version1 and portable envelopes1–5/7 are retained. F1/native-v6 remains on the separate unmerged branch; it is safely rejected by this baseline rather than losing AI provenance. R2 does not merge F1 or claim to validate that branch's model inference.

Native documents keep all current hidden layers and referenced assets, masks, clipping/group relationships, blend/opacity/visibility, transforms and IDs. Duplicate assets remain shared immutably. The nested round-trip test compares all JSON-persistable fields; absent optional fields and explicitly undefined fields have the same native JSON representation. Destructive merges/flattening retain their existing confirmation/compatibility/pixel-validation guards and session Undo; original Chapter bytes remain separately retained. Native files persist the current editable document, not a cross-session Undo timeline.

The existing compositor uses 8-bit browser Canvas with encoded-sRGB component arithmetic for CPU blend paths, rather than linear-light/HDR compositing. The 16 modes follow W3C formulas and Canvas operation names; browser-native quantization can differ by a channel unit. There is no new CMYK/ICC/16-bit pipeline. Existing alpha/group/mask/clip parity tests cover preview and native-resolution exports in Chromium; alternative browser/color-profile behavior is not newly certified.

The existing 50-state / soft32MiB history policy, 48-layer count, group depth<=3, 48MiB immutable pool, native/worker/pixel limits and revision-safe save queue remain unchanged. Autosave is still debounced; abrupt process/device termination can lose the last unsaved edits. Failed graph/clipping operations do not partially record history. Existing native file/type/graph/asset validation and atomic persistence regressions are retained.

R1.1 `image-policy`, `image-decode`, Chapter store and database import transaction files are byte-identical to the starting HEAD. No import size/header/device/batch budget was weakened. The thumbnail worker validates source assets through the existing R1.1 predecode path before resized decoding.

## Thumbnail cache and resource contract

`thumbnailDocument` shares the exact existing isolated-root rendering contract with the worker. Root opacity/blend/visibility/clipping are normalized for a content thumbnail. Child visibility, ordering, opacity, blending, masks, effects, transform and content remain significant. Names/locks/link IDs do not affect rendering. Keys include canvas dimensions/global thumbnail scale and referenced immutable Blob identity, including clone/mask source references. Changes propagate to affected ancestors; unrelated roots reuse entries. Canvas size, asset replacement, content changes and Undo invalidate correctly.

Keys compare complete strings rather than short collision-prone hashes. Keys above32Ki UTF-16 units are deliberately uncached; <=48 such bounded entries are retained, plus small PNG URLs. This limits retained key storage to approximately3MiB (excluding temporary serialization/runtime overhead). Large/complex layers may re-render rather than retaining unbounded keys. Cache lifetime is the mounted Layers panel; leaving/hiding it releases its resources. The worker accepts an optional validated list of <=48 requested IDs and uses the same compositor; it is not a second graphics engine.

Full preview composition is still bounded and generally recomputes the preview; existing dirty rectangles only reduce presentation copying. R2 does not introduce tiled rendering, a new group cache, an unlimited history system, native-resolution zoom or a global GPU memory allocator. Those require separate profiling/scope. Rotation itself is presentation-only and requests no worker recomposition.
