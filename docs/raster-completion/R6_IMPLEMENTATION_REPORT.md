# R6 implementation report

Draft PR: https://github.com/barbonselvar/inkstrip-manhwa-studio/pull/16. Branch `codex/r6-color-adjustments-filters`, based on main `740720c1d5e141c7f52ecab83d2e505fea7183f0` (merged R3 PR14 and R5 PR15). No unrelated branch changes were imported. Main, production, PR6 and R7 are outside this work.

**Status: compatible pixel-processing scope implemented; full R6 remains incomplete because persistent advanced adjustment-layer settings require an approved native-format extension.** Existing persistent adjustment layers are retained and tested with their existing operations. No native document format or old color algorithms were changed.

## Delivered behavior

Raster Studio → Properties → Color & Filters opens a focus-trapped modal for one visible unlocked raster/paint layer. It shows native layer pixels before its mask, clipping, opacity, blending and effects; that target distinction is explicit in the UI. Each preview starts from the same rendered source, including its existing layer-local paint and color settings. The document composite and autosave remain committed-only. Before/after, Reset, Apply and Cancel are real pixel operations.

The modal offers numeric fields and sliders, per-channel Levels and Curves, a real alpha-weighted source histogram, graph/control-point editing (including touch), optional captured-selection coverage, and reusable factory/custom presets. Custom settings are validated, bounded and stored only in device preferences. Preset save failures are reported rather than falsely acknowledged.

Apply produces one ordinary PNG asset and one existing history transaction. The editable original is retained hidden directly below the processed layer, preserving clipping membership. The selected layer keeps its identity, hierarchy, geometry (including R5 masks/transforms), opacity, blend mode, clipping, mask and effects. Its baked paint/color fields are reset to prevent double processing. No original asset is overwritten. Undo restores the exact earlier document and Redo restores the processed layer. R3 painting on the processed raster creates a separate editable paint layer using the existing engine.

## Algorithms and color model

All documents still store 8-bit encoded-sRGB straight RGBA. Canvas2D/OffscreenCanvas compositing follows the existing browser pipeline. No ICC-managed editing, wide gamut, 16-bit document precision or GPU filter backend is claimed. Intermediate Gaussian sums use Float32 and scalar/LUT calculations use JavaScript floating point; lookup mappings keep floating point until pixel assignment; reused legacy operations retain their established 8-bit stage boundaries before PNG encoding. Multiple accepted destructive operations can accumulate quantization; use the retained original to restart.

| Operation                      | Actual algorithm                                                                                                                                                                                                                |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Brightness / contrast          | Reuse legacy additive brightness and exponential contrast around encoded midpoint 127.5; stable source, alpha untouched                                                                                                         |
| Levels                         | Clamp input black/white, exponent `1/gamma`, map to ordered output endpoints; composite RGB first, then independent R/G/B                                                                                                       |
| Curves                         | 2–16 strictly ordered integer input knots per RGB/R/G/B channel; shape-preserving cubic Hermite with Fritsch–Carlson tangent limiting; no local segment overshoot; composite then per-channel LUT with fractional interpolation |
| Histogram                      | All native source pixels, visible samples weighted by alpha; independent R/G/B bins; RGB display is Rec.709-weighted encoded luma                                                                                               |
| HSL                            | Conventional encoded-RGB ↔ HSL; wrapped hue, relative saturation and lightness toward black/white; optional six hue ranges with full effect within 30°, smoothstep fade to zero at 60°, with saturation gating to protect grays |
| Color balance                  | Reuse quadratic luma-range weights `(1-L)^2`, `2L(1-L)`, `L^2`; optional encoded-luma preservation with chroma shrinking into gamut                                                                                             |
| Exposure / gamma               | Decode sRGB transfer, multiply linear light by `2^stops`, clamp, re-encode, apply encoded `1/gamma`; distinct from unchanged legacy encoded-exposure setting                                                                    |
| Vibrance / saturation          | Reuse existing chroma-distance vibrance around Rec.709 encoded luma; positive gain scales by `1-chroma`, protecting saturated pixels; existing global saturation follows                                                        |
| Black and white                | Editable additive R/G/B percentage mix, default 21.26/71.52/7.22; encoded luma, not physical luminance                                                                                                                          |
| Invert / threshold / posterize | Visible RGB complement; inclusive luma cutoff; exact requested 2–256 channel levels. Threshold/posterize reuse existing implementations                                                                                         |
| Gaussian                       | Genuine normalized separable Gaussian kernel, sigma 0.1–32 and support `ceil(3*sigma)`; clamp borders                                                                                                                           |
| Box                            | Existing separable running-sum alpha-weighted box, radius 1–32; clamp borders                                                                                                                                                   |
| Motion blur                    | 1–63 symmetric line samples at the chosen angle, nearest integer positions; alpha-weighted RGB and clamped borders; documented discrete line, not a second Gaussian                                                             |
| Sharpen                        | Four-neighbor Laplacian high-boost with alpha-aware neighbor fallback                                                                                                                                                           |
| Unsharp mask                   | Source minus Gaussian, adjustable gain and difference threshold                                                                                                                                                                 |
| Add noise                      | Deterministic seeded uniform noise, monochrome or independent channel draws                                                                                                                                                     |
| Noise reduction                | Reuse existing 3×3 alpha-weighted edge-aware denoise, excludes large color differences                                                                                                                                          |
| Median                         | Per-channel alpha-weighted median over radius 1–3 neighborhood, ignores invisible samples                                                                                                                                       |
| High pass                      | Source minus Gaussian plus encoded middle gray 128                                                                                                                                                                              |
| Edge detection                 | Sobel gradient magnitude of encoded luma, normalized by 4; black means no edge                                                                                                                                                  |

Spatial operations preserve source alpha instead of expanding silhouettes. Gaussian/box/motion normalize premultiplied color and coverage so invisible RGB cannot produce colored fringes. Median weights by alpha; sharpen/Sobel mix weakly covered neighbors toward the current source color. Fully transparent RGB remains unchanged in the pixel engine; the existing Canvas/PNG boundary can canonicalize invisible color to zero. Captured selection crossfades the result once against the stable source. Filtering uses surrounding source pixels even outside the selected area; the selection limits where output is written.

## Transactions, cancellation and resource safety

The source is extracted through an isolated existing `ProRenderer`, at layer-native resolution before its mask/effects. Preview jobs run in separate workers with 100ms input debounce. Every parameter change terminates the previous worker; unmount/Cancel terminates source and processing workers. Late decode results are ignored and ImageBitmaps are closed. Apply waits for the encoded result to be displayed and verifies its parameter key. Apply errors remain visible in the modal. The captured immutable document identity and target are checked against live history before acceptance. Layer/document changes cancel the modal; they cannot redirect an operation.

Native dimensions are integer, at most 16384 per side and at most 4MP or the smaller device budget. PNG headers pass the existing image preflight before decode. Gaussian/motion/median/Sobel have an additional 128-million neighbor-work budget; oversized radii reject clearly rather than downsample silently. Existing layer48, asset64/48MB, source-combined, mask/selection and history limits remain enforced. Retaining originals consumes those budgets deliberately; resource rejection leaves document/assets unchanged.

## Native compatibility and blocked advanced adjustment layers

Internal version1 and envelope versions1–5/Dialogue7 are unchanged. Existing adjustment layers already filter visible siblings below in the same isolated group; clipped adjustments process their base stack. Mask-only mode cannot launch a color operation. Masks, density/feather/placement, opacity, visibility and supported blend modes still apply. Ordinary reorder/duplicate/delete and save/reopen remain provided by the established R2 pipeline. New pixel operations export through ordinary raster assets and are readable by current/older supported readers; SVG retains its existing explicit restrictions.

The new operation settings are not stored as hidden or unknown native fields. They are not presented as editable advanced adjustment layers. Advanced persistent channel Levels, variable Curves, HSL/linear exposure and new spatial filters remain **blocked by unapproved schema work**. This is a release acceptance dependency, so this report does not declare R6 fully complete.

A future approval proposal is envelope8 (6 is reserved by AI PR6; 7 by Dialogue), with a strictly validated optional layer processing stack, explicit algorithm version and ordered operations. Legacy1–5/7 would migrate with an absent stack preserving old pixels; new readers would retain existing feature requirements, and old readers would reject8. Dialogue plus advanced settings would also use8. AI6 integration must be coordinated separately rather than opportunistically accepted. This is a proposed design only: no format or migration was implemented.

## Limitations and integration

Advanced operations process one raster/paint layer, not a merged document, group, adjustment plane, vector or text object. Existing editable operations continue to cover other layer types. The modal preview is a local layer proof, not the final blended composite; masks/clipping/group effects are preserved and the committed/exported composite is tested separately. No new R4 selections were introduced. Very large kernels on large layers intentionally exceed the work budget. No physical Android, stylus pressure hardware, Firefox/Safari or ICC parity is claimed.

R3/R5 are in the actual base; their stroke finalization, local pressure preferences, commit acceptance and transform revision protections were retained. PR6 remains separate; future advanced format work must coordinate AI6/Dialogue7 reservations. The exact R6 branch has Vercel deployment disabled. Keep PR16 Draft and do not merge/deploy without user authorization.

Validation details, measured performance, final evidence and tested commit are recorded in `R6_TEST_REPORT.md` and `r6/validation.json` after the acceptance run.
